# logic.md — разбор логики режимов книга/музыка

Аудит поведения плеера в двух режимах: что устроено как, где реальные баги, где источники
«странного» поведения, и рекомендации. Ссылки на код — `файл:строка` по состоянию на main (9e38fbc).

## 1. Как это устроено сейчас (модель)

Ключевой факт, из которого растёт почти вся путаница: **контролы нижней панели ссылаются на разные
вещи**.

| Контрол | На что ссылается | Когда действует |
|---|---|---|
| Shuffle (Switch) | **живая очередь** (live queue) | сразу, перестраивает порядок |
| Audiobook (Checkbox) | **папка, открытая в браузере** | только при следующем старте этой папки |
| Speed (кнопка) | **играющая папка** (значение), но видимость — от браузера | сразу, меняет живую очередь |
| Прогресс-бар трека, время | живая очередь | — |
| Прогресс книги (file x/y, %) | живая очередь | — |

То есть рядом стоят переключатель «про то, что играет» и чекбокс «про то, где я сейчас стою в
браузере». Пока играет книга A, а в браузере открыта папка с музыкой B: shuffle заблокирован
(из-за A), чекбокс показывает режим B, кнопка Speed видима, активна и меняет скорость A. Это
консистентно с кодом, но не с интуицией — главный источник ощущения «странно себя ведут».

Режим очереди фиксируется в момент старта (`startQueue`, MainActivity:658): книга = sequential +
repeat off + saved position + per-folder speed; музыка = shuffle/repeat по живым настройкам +
скорость всегда 1.0. Дальше очередь живёт со своим режимом, а персистентный флаг abook может
уехать в сторону — см. баги ниже.

## 2. Реальные баги

### B1. Переключение Repeat в Settings ломает играющую книгу — HIGH — ✅ РЕШЕНО

Решено радикально: тумблер Repeat удалён, repeat всегда off (глобальный compile-time флаг
`Settings.REPEAT_ALL = false`, без UI). Описание исходной проблемы ниже оставлено для истории.

`onLoopChange` (MainActivity:239-244) безусловно ставит `repeatMode` на живой контроллер. Книжная
очередь обязана играть с `REPEAT_MODE_OFF` — иначе она никогда не достигнет `STATE_ENDED`:
resume-позиция не очистится, книга по кругу перейдёт на файл 1, а сервис продолжит сохранять
позицию (затирая прогресс началом книги).

**Фикс**: в `onLoopChange` не трогать контроллер, если `playingAbookState == true` (настройка
просто персистится и применится при следующем музыкальном старте — ровно как ведёт себя чекбокс
abook).

### B2. Чекбокс abook играющей папки расходится с режимом живой очереди — HIGH

Чекбокс не блокируется для папки, чья очередь сейчас играет. Изменение флага не трогает очередь
(задумано), но `onStart` при реконнекте (поворот, возврат в приложение) вычисляет `liveIsBook` из
**текущего** persisted-флага (MainActivity:376-378), а не из режима, с которым очередь стартовала.
Два сценария рассинхрона:

- Играет музыка из папки → ставим галочку abook → поворот экрана. `liveIsBook == true`:
  играющая шаффленная музыка объявляется книгой — shuffle блокируется, появляется бессмысленный
  прогресс книги; а если она была на паузе — очередь вообще убивается как «stale book».
- Играет книга → снимаем галочку → поворот. `liveIsBook == false`: UI считывает shuffle из движка
  (`shuffleState.value = c.shuffleModeEnabled`, MainActivity:398) — а там принудительный off от
  книги. Следующая музыка молча играет без шаффла — ровно то, от чего код в комментарии защищается.
  При этом сервис продолжает трекать позицию (его `bookFolderKey` никто не сбрасывал).

**Фикс**: записывать режим очереди в момент старта — флаг в extras медиа-айтемов
(`EXTRA_IS_BOOK` рядом с `EXTRA_PLAY_FOLDER_ID` в MusicScanner) — и в `onStart` читать его, а не
`Settings.isAbook`. Дополнительно (или вместо): блокировать чекбокс, пока его папка — живая
очередь, как уже блокируется shuffle.

### B3. Книга с подпапками (CD1/CD2/…) теряет режим книги — HIGH

Флаг abook проверяется только по точному ключу папки, без наследования:

- Тап по файлу-главе внутри подпапки книги (`playFile`, MainActivity:712): ключ — подпапка,
  `isAbook == false` → главы играют как **музыка**: с шаффлом, на 1.0, без сохранения позиции.
- «Play this folder» внутри подпапки — то же самое.
- Даже в плоской книге `playFile` строит очередь только из файлов текущей папки
  (`FolderCache.children`, не рекурсивно), тогда как `playFolder` — рекурсивно. Очередь из подпапки
  закончится на последнем файле подпапки, книга «обрывается»; и счётчик «file x/y» у такой очереди
  другой, чем при обычном старте книги.

**Фикс**: режим книги должен действовать на поддерево. Браузер уже несёт полный путь
(`pathState`), так что проверка «я внутри книги» — пройтись по ключам предков. Тогда: тап по главе
в любой подпапке строит **рекурсивную очередь от папки-книги** со стартом на этом файле (тап =
«перейти к главе», позиция сохраняется дальше), а чекбокс в подпапках показывает унаследованное
состояние (и, логично, заблокирован).

### B4. Гонка при завершении книги: подписи могут не очиститься — LOW (проверить на устройстве)

На `STATE_ENDED` сервис чистит очередь (`player.clearMediaItems()`, PlayerService:128), а активити
чистит подписи только при `mediaItemCount > 0` (MainActivity:356). События до контроллера идут
асинхронно: если к моменту доставки `STATE_ENDED` очистка уже отражена, guard не сработает и
title/прогресс зависнут на экране. Статически не доказать — пункт для ручной проверки.

## 3. Странности UX (работают «как написано», но не как ожидаешь)

### U1. Пауза книги убивает её очередь — асимметрия с музыкой — MEDIUM

Два места:
- Реконнект (`onStart`, MainActivity:385-393): книга на паузе → очередь уничтожается. Сценарий:
  поставил книгу на паузу в шторке, открыл приложение — уведомление исчезло, «ничего не играет»,
  надо идти в папку и жать Play (с отмоткой −15 с).
- Навигация (`clearNowPlayingIfStopped`, MainActivity:508): вышел из папки книги, пока она на
  **паузе** (не только стоп) — очередь убита.

Музыка на паузе в обоих случаях переживает. Итог: большая кнопка Play значит разное в зависимости
от того, книга была или музыка — для пользователя это лотерея. Понимаю мотив (залипшая книжная
очередь блокировала shuffle при «ничего не играет»), но это лечение симптома: корень был в
UI-гейтинге, не в очереди.

**Рекомендация**: паузу книги считать обычной resumable-паузой — очередь живёт, Play продолжает с
места, shuffle остаётся заблокированным (книга реально live), прогресс книги виден. Убивать
очередь только на стоп/конец. Тогда и спец-ветки в `onStart`/`clearNowPlayingIfStopped` сжимаются.

### U2. Смешанные референты контролов (см. §1) — MEDIUM

Минимальные шаги, не ломая дизайн:
- **Speed**: видимость привязать к `playingAbook`, а не к «в браузере открыта папка»
  (MainActivity:1500). Сейчас: на home-экране при играющей книге скорость недоступна, а при
  браузинге чужой папки — доступна. Должно быть наоборот: скорость показывается ровно тогда, когда
  есть книга, которой она принадлежит. Бонус: пропадает вечно-серая кнопка при музыке.
- **Abook-чекбокс**: это свойство папки, а стоит он среди контролов воспроизведения. Логичнее
  перенести его в зону браузера (рядом с «Play this folder» / заголовком папки) — тогда референт
  очевиден. Если оставлять на месте — хотя бы блокировать для играющей папки (см. B2).
- Сейчас задать скорость книге, не запуская её, нельзя (кнопка активна только при `playingAbook`).
  С переносом скорости «к книге» это решается само; иначе — допустить открытие диалога для
  открытой в браузере книги (запись через `Settings.setSpeed` по ключу папки уже есть).

### U3. Включил abook играющей папке — ничего не происходит — MEDIUM

Прямое следствие дизайна «флаг действует со следующего старта» плюс resume-ветки `togglePlay`
(MainActivity:592: та же папка на паузе → `controller.play()` со старым режимом). Единственный
способ применить флаг — запустить другую папку и вернуться, либо перезапуск. Никакого фидбека, что
галочка «сработает потом», нет.

**Рекомендация**: после фикса B2 (блокировка чекбокса играющей папки) проблема исчезает сама:
поменять режим можно будет только у не-играющей папки, и следующий Play честно его применит.

### U4. Прогресс книги в процентах — по числу файлов, не по времени — MEDIUM

`bookFraction = (mediaIndex + fileFrac) / mediaCount` (MainActivity:1413). При главах разной длины
(типично: финальный файл-«приложение» на 5 минут против глав по часу) процент врёт. В
`DOC/todo.txt` уже лежит хотелка «3 ч 12 мин из 9 ч 40 мин» — это та же проблема.

**Рекомендация**: кэшировать длительности файлов (колонка в `FolderCache`; заполнять лениво —
ExoPlayer узнаёт duration каждого сыгранного файла бесплатно, остальные можно добрать
`MediaMetadataRetriever` в фоне один раз). Тогда и точный %, и «X ч из Y ч». Пока длительностей
нет — честнее показывать только «file x/y» и убрать %, либо подписать его как приблизительный.

## 4. Мелочи (low)

- **Повторная отмотка −15 с накапливается**: resume книги = saved − 15 с; пауза сразу после
  resume сохраняет уже отмотанную позицию; каждый цикл «вошёл-вышел» съедает ещё 15 с. Лечится
  отметкой «позиция уже с отмоткой» или отмоткой только если с сохранения прошло > N минут.
- **Путь над названием трека мигает**: subtitle — путь ниже корня (MusicScanner:195), у треков
  прямо в корне он пустой → при рекурсивном плейлисте строка пути появляется/исчезает от трека к
  треку. Можно показывать имя корня как минимум.
- **`togglePlay` сравнивает только `documentId`** (MainActivity:588), без treeUri — теоретическая
  коллизия между корнями (сам `Settings.bookKey` от неё защищается). Сравнивать с ключом папки.
- **Дублирующийся комментарий** «Reconcile the shuffle toggle…» в `onStart` дважды
  (MainActivity:369-375 и 394-396) — остаток рефакторинга, один убрать.
- **«Default speed» в Settings** применяется только к книгам без своей скорости; музыка всегда
  1.0 (намеренно). Из названия это не следует — стоит уточнить подпись (например, «Default book
  speed»).
- **Shuffle сохраняется в instance state** (поворот), но не персистится (перезапуск) — намеренно,
  но после смерти процесса с живой музыкальной очередью UI берёт значение из движка, так что
  рассинхрона нет; просто зафиксировать как ожидаемое.

2. **B2** — режим очереди фиксировать на старте (extras-флаг) + блокировать чекбокс играющей папки.
3. **B3** — наследование abook на поддерево + рекурсивный `playFile` для книг.
4. **U1** — пауза книги = обычная пауза (пересмотреть «end leftover queue» от 9e38fbc).
5. **U2** — speed к книге, abook-чекбокс к браузеру.
6. **U4** — кэш длительностей → честный прогресс «X ч из Y ч».
7. §4 — по остаточному принципу.

Пункты 1–3 — кандидаты на формат tofix (по одному коммиту на проблему); 4–6 — сначала обсудить,
они меняют поведение, к которому могла выработаться привычка.
